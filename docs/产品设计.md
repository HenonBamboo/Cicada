# 知了 · 产品设计

> 本文档是功能逻辑的唯一依据。代码与本文档冲突时，以本文档为准；需求变化时先改本文档，再改代码。

## 1. 产品定位

**知了（Cicada）**：一个 Windows 桌面端的个人任务与项目记录工具。

- **核心**：你只管说，它来整理。
- **一句话定位**：说一声就记下，说一声就办妥。
- **名字**："知了"即"知道了"——你说一句，它回一句"知了"。同时是夏天的蝉，自然、亲切。

### 主打：省心——金蝉脱壳

- **用户感受**：说一声就不用管了。像有个靠谱的秘书替你记着，你可以放心忘掉。
- **寓意**：金蝉脱壳。杂事往它身上一"脱"，你就轻装前行。
- **独有之处**："只说不点"。界面是一块安静的展示板，唯一的编辑者是 AI。同类产品要么让你自己动手整理，要么只是 AI 帮你写报告，没有把"编辑权"完全交出去的。
- **语气**：回应感。每次执行完都回一句"知了"，有来有往，但不啰嗦、不打扰。
- Logo、问候语、空状态、通知等所有文案和视觉，都围绕"省心、轻松"来设计。

### 三个特色

1. **只说不点**：除了勾选完成，所有增删改查都通过输入框交给大模型执行。
2. **一直在身边**：便利贴常驻桌面，全局快捷键随时记录。
3. **自动回顾**：每天的完成情况进入热力图，周报、月报、年报自动生成。

### 目标用户与场景

个人日常记录：工作待办、生活琐事、个人项目推进。单用户、单机，数据保存在本机；使用 AI 功能时，会把完成本次请求所需的文字或图片发送给用户所选的模型服务商（见 4.8）。

## 2. 核心原则

| 原则 | 说明 |
|---|---|
| 写操作只走输入框 | 新建、修改、删除、移动、改状态、改日期，全部由大模型通过工具调用完成 |
| 唯一的手动写操作 | 勾选 / 取消勾选**今日任务**的完成状态（主界面和便利贴都可以） |
| 读操作不受限 | 滚动、展开/折叠、切换视图、悬停/点击热力图查看、查看报告、拖动便利贴等不改数据的操作都允许 |
| 能力边界 | 大模型只做：任务和项目的增删改查、提醒、总结。其他请求礼貌拒绝并提示能做什么 |
| 不能手改，所以必须能后悔 | 歧义先问、危险操作先确认、所有操作可撤销、每天自动备份 |

## 3. 主界面

### 3.1 布局（单页）

```
┌──────────────────────────────────────────────────┐
│ 知了                                    ─  □  ✕  │ ← 自定义标题栏
│                                          ⚙ 设置  │
│            晚上好，今天还剩 2 件事                  │ ← 问候语
│   ┌[任务 ⇄ 项目]─────────────────────────────┐    │
│   │ 说点什么…                       🖼   ➤   │    │ ← 输入框
│   └──────────────────────────────────────────┘    │
│   ┌ 回复区：执行结果 / 查询结果 / 追问 / 确认 ┐    │
│   ▦▦▦▦▦▦▦▦▦▦▦▦▦ 完成热力图 ▦▦▦▦▦▦▦▦▦▦▦▦▦  [报告]  │
│   ┌──── 任务 ────────┐  ┌──── 项目 ────────┐      │
│   │今日/遗留/已完成/之后│  │  树状 | 文件夹    │      │
│   │  （区域内滚动）    │  │  （区域内滚动）    │      │
│   └──────────────────┘  └──────────────────┘      │
└──────────────────────────────────────────────────┘
```

### 3.2 两种状态

| 状态 | 表现 |
|---|---|
| 静息态 | 问候语和输入框居中；任务区和项目区收起，只显示摘要（如"今日 3 项 · 项目 2 个"） |
| 聚焦态 | 点击输入框后，问候语和输入框平滑上移，热力图、任务区、项目区展开；两个区域各自滚动，不影响整个页面 |

- 退出聚焦态：点击空白处或按 `Esc`。回复区有内容正在显示时不自动收起。
- 状态切换必须有顺滑的过渡动画（可在设置中关闭动效）。

### 3.3 输入框

- **模式切换**（左上角）：`任务` / `项目`。两种模式使用不同的系统提示词。输入框内按 `Tab` 切换（主界面、便利贴、快速记录统一），`Shift+Tab` 保留为标准焦点导航。
- **模式不符时**：内容明显属于另一种模式（如在任务模式说"新建一个项目"），模型提示是否切换，而不是硬塞进去。
- **总结**：在两种模式下都能用（"总结一下这周"）。
- **图片**：点击按钮选择，或 `Ctrl+V` 粘贴截图（配合系统 `Win+Shift+S`）。用途是识别截图、白板照片、手写清单，拆成任务或项目结构。图片只识别，不长期保存：处理期间临时存放在 `inbox/` 目录，请求完成、放弃或超过 7 天后删除（见 4.6）。单次请求最多 4 张图片，单张解码后不超过 8 MiB，合计不超过 20 MiB；图片路径只允许指向数据目录 `inbox/` 内的普通文件。
- **输入上限**：单次文字输入最多 20,000 字。
- **快捷键**：`Enter` 发送，`Shift+Enter` 换行。
- **不支持语音输入**。

### 3.4 回复区

大模型的所有反馈都显示在这里，是一张轻量卡片，不是完整的聊天记录：

- **执行结果**："知了，已添加 2 件事：……"，同时在列表中高亮被改动的条目。
- **查询结果 / 总结**：以列表或 Markdown 显示。
- **追问**：匹配到多条或信息不全时，先问再做。
- **确认**：危险操作的预览，点击"确认"或回复"确认 / 好 / 可以"等简短肯定语后执行；点击"算了"或输入其他内容则取消（见 4.4）。
- **撤销提示**：每次执行后显示"撤销"按钮（等同于说"撤销刚才的操作"）。
- 确认、取消、撤销三个按钮直接调用 Rust 命令执行，不再经过模型理解。
- 只保留最近一轮的回复；新的输入会替换旧的回复。
- 回复正文按块级 Markdown 显示；任务和项目标题按行内 Markdown 显示，原始 HTML 只作为文字处理。
- 输入保留 Markdown 原文；模型提取纯文本标题，详细说明保留在 Markdown 备注中。三个输入入口用 `↑/↓` 浏览本入口、本模式最近 50 条输入并恢复未发送草稿；多行内容仅在光标位于全文开头或结尾时进入历史。

## 4. 大模型约束

### 4.1 三层防护

1. **程序层**：使用工具调用（Function Calling）。模型不能直接写数据，只能调用白名单工具。
2. **提示词层**：定义角色、当前模式、能力边界和拒绝规则。
3. **校验层**：Rust 端对每次工具调用做校验（层级上限、日期合法、ID 存在等），不合法则拒绝执行并告知原因。

### 4.2 工具白名单

| 范围 | 工具 | 说明 |
|---|---|---|
| 任务 | `task_add` | 标题、计划日期（默认今天）、可选：截止时间、提醒时间、备注、关联项目节点 |
| | `task_update` | 修改任意字段 |
| | `task_delete` | 需确认 |
| | `task_set_done` | 标记完成 / 未完成 |
| | `task_query` | 按日期、状态、关键词、范围查询 |
| 重复任务 | `recur_add` / `recur_update` / `recur_delete` / `recur_query` | 规则如"每天""每周一""每月 1 日" |
| 项目 | `project_add` | 新建项目（第 1 层） |
| | `node_add` | 指定父节点新增子节点（最多到第 3 层） |
| | `node_update` / `node_move` / `node_delete` | 删除需确认，删除节点会连同子节点一起删除 |
| | `node_set_done` | 标记完成 / 未完成 |
| | `project_set_status` | 进行中 / 已完成 / 已归档 |
| | `project_query` | 查询项目结构和进度 |
| 联动 | `node_schedule_today` | 把项目节点安排为今日任务（生成关联任务） |
| 通用 | `summarize` | 范围（任务/项目/全部）+ 时间段 |
| | `report_get` | 读取已生成的周报/月报/年报 |
| | `ask_clarify` | 向用户追问 |
| | `undo_last` | 撤销上一次操作 |

### 4.3 安全机制

- **歧义先问**：匹配到多条时追问，不猜。
- **危险操作先确认**：删除、一次修改超过 3 条，先给预览，确认后执行。
- **撤销**：每次操作（包括手动勾选）写入操作日志，可撤销最近的操作，支持连续撤销（规则见 4.5）。
- **事务**：一轮对话中的所有写操作作为一个整体原子提交，任何一步失败则全部不生效，数据保持原样（流程见 4.4）。
- **隐私与成本**：查询类请求通过 `*_query` 工具检索相关数据，不把全部数据塞进提示词。
- **连续对话**：各入口、各模式共享近 24 小时最近 6 轮已完成输入、识图文字与执行摘要，历史最多 12,000 字符，本轮输入不因历史截断。历史仅供指代理解；对已有对象写入前必须查询当前数据库，不能重做旧指令或信任历史编号。

### 4.4 一轮请求的处理流程

一轮请求 = 用户的一次输入，到回复区给出最终结果为止。分六步，**只有第 5 步持有数据库写事务**，等待模型或等待用户确认时都不占用写锁。

1. **登记**：输入先写入 `inbox`（见 4.6），获得稳定的请求 ID，并记下输入时间、当时的业务日期、模式、来源窗口。
2. **理解意图**：调用模型，用 `intent_checklist` 逐项引用原文并核对覆盖，每个写工具关联 `intent_id`，有未处理要求时不能提交部分结果。查询类工具（`*_query`、`report_get`）立即执行；写类工具**不立即执行**，而是追加到本轮的"变更计划"，返回"已计入计划"和临时引用（如 `$1`），以便引用本轮新建对象。查询意图通过 `intent_resolve` 记录有依据的结果。
3. **校验**：模型结束后，Rust 对整份计划逐条做业务校验（ID 存在、层级、日期等），并记录每个被涉及对象的当前版本号（`version`）。不合法则整份计划作废，回复说明原因。
4. **必要时确认**：计划含删除、或影响超过 3 条时，生成预览，计划连同对象 ID、具体变更和版本号一起保存为"待确认"，本轮暂停。
   - 待确认在用户输入新内容、点击"算了"或 10 分钟后失效。
   - 追问（`ask_clarify`）同理：保存本轮上下文，用户的下一句话视为回答；回答后继续第 2 步。
5. **原子提交**：开启一个写事务，先按版本号重新校验——涉及的对象若已变化，放弃提交并重新生成预览；否则依次执行全部变更，同时写入 `op_log`（同一请求 ID 为一组）和 `completions`，一起提交。
6. **返回结果**：发数据变更事件，写操作摘要由实际提交的预览生成，显示项目路径和名称，不向用户报内部编号；混合查询的回答也保留。显示撤销按钮，`inbox` 中该请求标为已完成。

- 同一请求 ID 只会提交一次：重试时若发现该 ID 已提交，直接返回上次结果，不重复执行。
- 手动勾选不经过模型，但同样走第 5 步（单条变更、版本校验、写 `op_log`）。

### 4.5 统一业务服务与撤销规则

- **统一业务服务层**：模型工具、手动勾选、定时任务（日切、重复任务、提醒）共用同一套 Rust 业务服务，任务和项目的规则（联动、完成记录、校验）只在这一处实现，不在各模块分别推断。
- **操作分组**：每组操作记录来源——`对话`、`手动勾选`、`系统`（日切、重复任务生成、报告、备份）。
- **撤销范围**：
  - "撤销"只针对**用户操作**（对话、手动勾选），按时间倒序逐组撤销，支持连续撤销；系统操作不会成为"撤销刚才的操作"的对象。
  - 撤销按 `op_log` 快照还原该组涉及的全部数据（含 `completions`）。若其中某个对象之后被其他操作改过（版本号不一致），拒绝撤销并说明是哪一条。
  - 设置修改不进入撤销栈，在设置页直接改回即可。
  - 撤销本身也写入 `op_log`，但不可"撤销撤销"。
- **跨日**：日切后，已归档的完成记录不能手动取消勾选；通过对话把过去某天的任务改为未完成需要确认，确认后删除对应的完成记录，热力图和尚未生成的报告随之变化，已生成的报告不自动改写。

### 4.6 收件箱

所有输入（主界面、便利贴、快速记录）都先进入收件箱，再处理。正常联网时用户感受不到它；离线、未配置模型或需要用户介入时，它负责暂存。

| 状态 | 含义 |
|---|---|
| 已暂存 | 已写入本地，等待处理（离线、未配置模型时停在这里） |
| 处理中 | 正在调用模型 |
| 待确认 | 需要用户确认危险操作，或需要回答追问 |
| 已完成 | 已提交，记录处理结果摘要 |
| 失败 | 多次重试仍失败，或校验不通过 |

- **快速记录**：输入写入收件箱成功后立即关闭输入条，后台处理，处理完发 Windows 通知。
- **离线**：提示"已暂存，恢复后自动处理"。恢复后按输入顺序自动处理；网络类错误自动重试（间隔递增，最多 5 次），之后标为失败。
- **时间上下文**：处理暂存内容时，提示词注入输入当时的时间和业务日期，"今天/明天"按输入时理解，不按处理时理解。
- **离线后的危险操作**：删除、批量修改即使在恢复后自动处理，也只到"待确认"，不自动执行。
- **未配置模型**：输入进入"已暂存"，回复区显示"还没配置模型，已暂存，配置好后处理"，并提供前往设置的入口；不会执行任何写入，也不会伪装成执行成功。
- **图片**：随请求临时保存在 `inbox/` 目录，请求完成、放弃或 7 天后删除；超过 7 天未处理的请求标为失败，并提示图片已清理。
- **入口**：收件箱有未完成项时，输入框下方显示"收件箱 n 条"；点击后在回复区列出，每条可以"重试"或"放弃"（这是对待处理输入的操作，不是对任务数据的编辑）。托盘菜单和失败/待确认通知也可以打开它。
- **便利贴与快速记录的确认/追问**：这些窗口不承载确认预览。需要确认或追问时，请求进入"待确认"，通知用户，点击通知打开主界面并在回复区继续。
- 已完成的收件箱记录保留 30 天后清理（只保留结果摘要，不含图片）。

### 4.7 提示词

内部使用的提示词全部对用户可见、可调整，方便根据所用模型和个人习惯微调。

- **可调整的提示词**：

  | 提示词 | 用途 |
  |---|---|
  | 通用角色 | 角色、语气（"知了"的回应感）、能力边界与拒绝话术 |
  | 任务模式 | 任务模式下的补充说明（日期理解、提醒、重复规则等） |
  | 项目模式 | 项目模式下的补充说明（层级、节点命名等） |
  | 图片识别 | 识图模型如何把图片转成文字清单 |
  | 总结 | `summarize` 的输出结构 |
  | 周报 / 月报 / 年报 | 报告的结构与风格 |
  | 问候语 | 问候语的生成规则 |

- **存放**：内置默认版本随应用发布（Rust 端编译进程序）；用户修改后的版本以 Markdown 文件存放在 `%APPDATA%\Cicada\prompts\`，存在则优先使用，否则使用默认版本。
- **变量**：提示词中可使用占位符，由 Rust 在调用前填充，如 `{{now}}`、`{{business_date}}`、`{{day_cutoff}}`、`{{week_start}}`、`{{mode}}`。设置页列出全部可用变量；未知变量保存时提示。
- **不可调整的部分**：工具定义（名称、参数结构）、本轮数据上下文和安全校验由程序生成，不出现在可编辑的提示词里。改提示词只影响"提示词层"，**工具白名单和 Rust 校验始终生效**，提示词写坏了也不能越权改数据。
- **设置页功能**：查看与编辑、恢复默认、与默认版本对比、预览完整系统提示词及工具定义（只读，含程序生成部分）、打开提示词文件夹。AI 优化只产生候选稿，用户明确采用才保存；修改从下一轮请求起生效。
- **默认版本更新**：应用升级时如果某个默认提示词变了，而用户改过该提示词，在设置页标注"默认版本已更新"，由用户选择保留自己的或改用新默认版本，不自动覆盖。
- 提示词文件纳入备份。

### 4.8 数据发送与权限

- **发送范围**：只发送完成本次请求所需的内容：用户输入、必要的查询结果、图片。不发送整个数据库和配置文件；API Key 只作为请求凭据发给对应服务商。
- **接口要求**：Base URL 支持 HTTP 和 HTTPS；HTTP 会明文传输请求内容和 API Key，只应连接用户信任的服务。API Key 按“服务商 + 接口来源（scheme、host、port）”隔离，接口来源变化后必须重新填写。
- **用户可见的说明**：设置页和首次启动引导中写明"数据保存在这台电脑上；使用 AI 功能时，会把完成本次请求所需的文字或图片发送给你选择的模型服务商"。
- **日志**：应用日志不记录 API Key、请求头中的凭据；默认不记录完整提示词和模型回复，调试模式下记录时同样脱敏。
- **窗口权限**：按窗口职责限制可调用的 Tauri 命令（Tauri capabilities），Rust 端仍做业务校验：

  | 窗口 | 允许 |
  |---|---|
  | 主窗口（含设置、报告） | 全部命令 |
  | 便利贴 | 读取今日任务 / 项目结构、勾选今日任务、提交输入、窗口自身状态 |
  | 快速记录 | 提交输入、关闭自身 |

## 5. 任务

### 5.1 字段

标题、计划日期、状态（未完成/已完成）、创建时间、完成时间；可选：截止时间、提醒时间、备注、重复规则 ID、关联项目节点 ID。

### 5.2 分区

| 分区 | 内容 | 可勾选 |
|---|---|---|
| 今日 | 计划日期为今天的任务 | ✅ |
| 遗留 | 之前没完成、自动滚入今天的任务，标注"已延期 n 天" | ✅（遗留任务也属于今日任务） |
| 已完成 | 今天完成的任务 | ✅（可取消勾选） |
| 之后 | 计划日期在明天及以后的任务，按日期排列，默认折叠 | ❌（到了当天自动进入"今日"） |

### 5.3 日切

- 日切时间默认 `00:00`，可在设置中修改（如 `04:00`）。
- 日切时：
  - 当天已完成的任务归档（进入热力图和报告数据，不再显示在已完成区）；
  - 未完成的任务自动滚入新的一天，延期天数 +1；
  - 根据重复规则生成新一天的任务。
  - 以上由统一业务服务执行，操作日志来源记为"系统"，不进入用户的撤销栈（见 4.5）。
- **补跑**：应用启动时检查上次日切时间，补执行错过的所有日切、重复任务生成和报告生成。
- 延期超过 7 天的任务，问候语会顺带问一句"这条还要做吗？"。

### 5.4 提醒

- 说"下午 3 点提醒我开会"→ 创建带提醒时间的任务。
- 到点弹出 Windows 通知，点击通知打开主界面。
- 应用未运行时错过的提醒，下次启动时汇总通知一次。

### 5.5 重复任务

- 规则：每天、每个工作日、每周 X、每月 X 日、每年 X 月 X 日。
- 每次日切时按规则生成当天任务；规则本身可通过对话修改或删除。

### 5.6 报告

| 报告 | 生成时间 | 数据范围 |
|---|---|---|
| 周报 | 每周第一天日切后（周起始日可设置） | 上一周归档的任务和项目节点完成情况 |
| 月报 | 每月 1 日日切后 | 上个月 |
| 年报 | 每年 1 月 1 日日切后 | 上一年 |

- 由大模型基于归档数据生成，存为 Markdown，可导出。
- 查看入口：热力图旁的"报告"按钮（只读列表），或说"看看上周周报"。

## 6. 热力图

- 每格代表一天，颜色越深当天完成越多。默认显示近一年。
- 统计范围：任务完成数 + 项目节点完成数。一件事只记一次：关联了项目节点的任务完成时，计为 1 件"项目"（见 7.4）。
- 悬停显示："10 月 17 日 · 任务 4 · 项目 2"。
- 点击某天：在回复区显示当天的完成清单（只读）。
- 配色跟随主题。

## 7. 项目

### 7.1 结构

- 可以有多个项目。
- 层级：**项目（第 1 层）→ 第 2 层 → 第 3 层**，最多三层，含项目本身。
- 节点字段：标题、状态、备注、可选截止时间、创建时间、完成时间、排序。

### 7.2 状态

- 节点：未完成 / 已完成。
- 父节点显示进度（如 `3/5`）。子节点全部完成时，模型在回复中询问是否把父节点也标为完成。
- 项目：进行中 / 已完成 / 已归档。已归档的项目折叠在列表底部。

### 7.3 视图

- **树状**：类似脑图的分支视图。
- **文件夹**：可展开折叠的缩进列表。
- 切换视图、展开折叠属于读操作，可以点击。

### 7.4 任务与项目联动

- 说"把项目 A 的'写接口文档'安排到今天"→ 生成一条关联该节点的今日任务。
- **一个节点同时最多一条未完成的关联任务**。再次安排时复用已有任务（改计划日期），不重复生成；已完成的关联任务作为历史保留。
- **双向同步**：勾选关联任务 ↔ 节点完成；取消勾选 ↔ 节点取消完成。无论从哪一边操作，两边状态一起改，作为同一组操作写日志、一起撤销。
- **完成只记一次**：一次"任务 + 节点"同步完成只写一条 `completions`，类型记为"项目"，同时记下任务 ID 和节点 ID。热力图和报告按这条记录统计；报告中可写作"完成项目节点 n 个（其中 m 个通过今日任务完成）"。
- **删除节点**：确认预览中列出受影响的未完成关联任务，确认后这些任务一并删除。已有的完成记录保留（`completions` 中存有标题和所属项目的快照），热力图和报告不受影响。
- **删除关联任务**：只删任务，节点保持原状态。

## 8. 问候语

- **更新时机**：打开应用、时间段变化（早晨/上午/中午/下午/晚上/深夜）、出现重要变化（今日任务全部完成、项目达到里程碑、出现长期延期任务）。
- **内容依据**：时间、今日剩余任务数、连续完成天数、快到期的任务和项目。
- **语气**：亲切、简短、不说教，带"知了"的回应感。
- 结果缓存，不必每次调用模型；离线或失败时使用本地模板（如"晚上好"）。
- 同次请求还生成任务/项目输入示例和空状态提示，按业务日期、时段、数据和提示词指纹缓存。按钮、错误、权限、更新与隐私文字保持固定。

## 9. 便利贴与快速使用

### 9.1 便利贴

- **形态**：小窗（默认约 280×360），无边框圆角，半透明纸感卡片。
- **内容**：上方今日任务（可勾选），底部一行迷你输入框（默认任务模式）。
- **多张**：默认一张"今日任务"；可以为某个项目单独开一张，显示树状结构和紧凑输入栏，初始项目模式，未明确指定其它项目时默认使用当前绑定项目。绑定由后端窗口身份确认，原始输入不被改写。所有可编辑输入栏通过 `Tab` 切换模式并显示当前模式文字。
- **窗口行为**：
  - 可置顶，透明度可调；
  - 拖到屏幕边缘吸附，可选贴边自动隐藏；
  - **锁定模式**：鼠标穿透，像壁纸一样不挡操作（通过托盘菜单解锁）。
- **颜色**：跟随主题，或单独选黄、粉、蓝、绿。
- **记忆**：记住每张便利贴的位置、大小、颜色；默认启动只显示主窗口，用户开启“启动时显示便利贴”后才随启动恢复。
- **切换**：双击便利贴打开主窗口；主窗口一键收成便利贴。

### 9.2 全局快捷键快速记录

- 默认 `Ctrl+Alt+Space`（可自定义），在任何软件里弹出屏幕居中的输入条。单个组合被占用时，不影响另外两个全局快捷键。
- 输入后按 `Enter`，内容写入收件箱后输入条立即消失，后台处理，处理完弹出 Windows 通知；需要确认或追问时，通知引导到主界面（见 4.6）。
- `Tab` 切换任务/项目模式。
- `Esc` 取消。

### 9.3 托盘与启动

- 关闭主窗口时缩到系统托盘，不退出。
- 左键托盘图标打开主窗口，右键打开菜单；菜单包含打开主窗口、显示/隐藏便利贴、解锁所有便利贴、快速记录、退出。便利贴上的锁只锁定当前一张，托盘入口用于统一解除鼠标穿透。
- 开机自启动（可关）；单实例运行。

### 9.4 每日回顾

- 每晚固定时间（默认 21:30，可设置、可关闭）弹出通知："今天完成了 5 件，明天要做什么？"
- 点击通知打开快速记录输入条。

| 提示词 | 查看/编辑各提示词、恢复默认、与默认对比、预览完整系统提示词、打开文件夹（见 4.7） |

| 快捷键 | 快速记录、显示/隐藏主窗口、显示/隐藏便利贴 |
| 启动 | 开机自启、启动时显示便利贴 |
| 报告 | 是否自动生成周报/月报/年报 |

设置页始终保持单列阅读顺序；普通窗口随可用空间展开，全屏时内容区最大宽度为 960px 并居中，控件和分组内容不变。

## 11. 数据

### 11.1 存储位置

`%APPDATA%\Cicada\`

```
Cicada/
├── cicada.db          SQLite：所有结构化数据
├── config.json        用户设置（不含 API Key）
├── reports/           周报、月报、年报 Markdown
│   ├── weekly/   YYYY-Www.md
│   ├── monthly/  YYYY-MM.md
│   └── yearly/   YYYY.md
├── prompts/           用户修改过的提示词（见 4.7）
├── inbox/             收件箱请求的临时图片（见 4.6）
├── logs/              应用日志（脱敏）
└── backups/           备份 zip，保留最近 30 份
```

开发版本（debug 构建）使用独立目录 `%APPDATA%\Cicada-dev\`，与正式数据完全隔离。

### 11.2 主要数据表（草案）

| 表 | 用途 |
|---|---|
| `tasks` | 任务 |
| `recur_rules` | 重复任务规则 |
| `nodes` | 项目和项目节点（`parent_id` 为空即项目，`depth` 1–3） |
| `completions` | 完成事件（业务日期、类型、任务 ID、节点 ID、标题与所属项目快照），热力图和报告的数据来源 |
| `op_log` | 操作日志（请求 ID / 分组、来源、操作前后快照、是否已撤销），用于撤销 |
| `inbox` | 收件箱：请求 ID、来源、模式、输入时间、业务日期、内容、图片路径、状态、重试次数、待确认计划、结果摘要 |
| `pending_plans` | 待确认的变更计划（可并入 `inbox`）：变更列表、涉及对象 ID 与版本号、过期时间 |
| `reports` | 报告索引 |
| `greetings` | 问候语缓存 |
| `stickies` | 便利贴窗口状态 |
| `meta` | 上次日切时间、上次备份时间、数据库结构版本等运行状态 |

- `tasks`、`nodes`、`recur_rules` 都有 `version` 字段，每次修改 +1，用于确认前后的冲突检测和撤销校验（见 4.4、4.5）。

### 11.3 备份与恢复

- **范围**：`cicada.db`（用 SQLite 在线备份，保证一致性）、`reports/`、`config.json`、`prompts/`，打包为一个 zip，内含清单 `manifest.json`（应用版本、数据库结构版本、创建时间、各文件校验值）。**不含** API Key 和 `inbox/` 临时图片。
- **触发**：
  - 每个业务日第一次需要时备份一次：应用启动时、或常驻运行中发生日切时（取先到者）；
  - 数据库迁移、导入、恢复之前各备份一次；
  - 设置中"立即备份"。
- **保留**：自动备份保留最近 30 份；手动和操作前备份单独计数，保留最近 10 份。
- **恢复步骤**：校验清单与文件 → 先备份当前数据 → 暂停定时任务和模型处理 → 替换数据库、报告、配置和提示词 → 如备份的结构版本较旧，执行迁移 → 按 `reports/` 中的文件重建报告索引（索引与文件不一致时以文件为准）→ 重新加载配置 → 通知所有窗口刷新 → 恢复定时任务。
- 恢复后若凭据管理器中没有对应服务商的 API Key，提示重新填写。

## 12. 非功能要求

- **轻量**：直接运行 EXE 尽量小于 15 MB，后台常驻时的私有驻留内存尽量小于 120 MB。
- **快速**：冷启动到可输入小于 1.5 秒；快速记录输入条弹出小于 200 毫秒。
- **流式**：模型回复流式显示。
- **兼容**：0.2.0 发布和验收范围为 Windows 11 x64；毛玻璃效果不可用时降级为纯色。其他 Windows 版本不作本次发布承诺。
- **更新**：代码和五个发布文件同步上传 GitHub/GitCode；程序启动仅检查 GitCode，用户确认后验证 Ed25519 清单签名、大小和 SHA-256，直接替换原路径 EXE、重启并确认就绪，失败恢复旧版。业务数据和凭据目录不变，不引入安装向导。0.1.0 首次升级需手动下载。
